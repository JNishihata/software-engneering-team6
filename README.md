# software-engneering-team6

神戸高専 ソフトウェア工学 チーム6 のリポジトリです。
成果物として **ToDo 管理アプリ**（HTML / CSS / JavaScript）を開発しています。

下記サイトで本アプリを使用することができます。
https://jnishihata.com/todo/

## アプリ概要

ブラウザだけで動作するクライアントサイドの ToDo 管理アプリです。
フレームワーク・ビルドツール・パッケージマネージャは使用しておらず、データはすべてブラウザの `localStorage` に保存されます。サーバーやアカウントは不要です。

## 主な機能

- タスクの追加・編集・削除・完了切り替え
- 期限による自動セクション分け（🚨 期限切れ / 📅 今日 / 📅 明日 / 📆 今週 / 📆 来週 / 📌 それ以降 / ∞ 期限なし）
- タイトル・メモのインクリメンタル検索
- 重要度（高 / 中 / 低）およびジャンルによる絞り込み
- ジャンルの追加（タスク入力フォームの「新規作成」）・リネーム・削除（ヘッダーメニューの「ジャンル管理」）
- 完了済みタスクの表示切り替え（ヘッダーメニュー）
- ブラウザを再読み込みしてもタスクを保持

## 実行方法

ビルド・インストールは不要です。以下のいずれかの方法で起動します。

```bash
# 1. ファイルを直接開く
open index.html
```

```bash
# 2. 静的サーバー経由で開く（file:// で localStorage が制限される場合）
python3 -m http.server
# → http://localhost:8000 をブラウザで開く
```

## 使い方

1. 右下の「＋」ボタンからタスクを追加する
2. 各タスクの「編集」「削除」ボタンで操作し、チェックボックスで完了を切り替える
3. 上部の検索欄・重要度・ジャンルで表示を絞り込む
4. ヘッダー右上のメニューから「ジャンル管理」「完了済みタスクを表示」を操作する

## データ構造

`localStorage` に以下の 2 つのキーで保存されます。

| キー | 内容 |
| --- | --- |
| `todoTasks_v1` | タスク配列 `{ title, note, due, priority, genre, completed }` |
| `todoGenres_v1` | ジャンル配列 `{ id, name }` |

- タスクの `genre` はジャンルの `id`（数値）を保持します。未設定の場合は `null` です。
- タスクに id はなく、`tasks` 配列内の位置（インデックス）が識別子として使われます。
- 旧形式のデータ（ジャンルを文字列で保持していたもの）は、起動時に自動で ID 管理へ移行されます。

## 実装メモ

- `render()` がフィルター条件に従ってタスク一覧を毎回作り直し、その後 `attachListeners()` でイベントを再登録します。要素は再生成されるため、描画後は必ずリスナーの付け直しが必要です。
- `tasks` / `genres` を変更したら、必ず `save()` / `saveGenres()` を呼んでください。呼び忘れるとリロード時に変更が失われます。
- タスク追加と編集は同一のフォーム（`#task-form`）を共有し、`editing` / `editing_task_index` フラグで動作を切り替えています。

## 命名規則

- タスク追加用モーダル：`task-add-modal`（JS 内：`taskAddModal`）
- ジャンル管理モーダル：`genre-edit-modal`（JS 内：`genreEditModal`）

## 開発の進め方

- `main` を統合ブランチとし、各自の作業ブランチから Pull Request を作成してマージします。
- テストフレームワークは導入していないため、変更後はブラウザ上で動作を手動確認してください。
