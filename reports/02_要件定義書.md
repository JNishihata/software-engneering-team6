## 1. システムの概要

- **目的**：複数の課題・タスクの締切を、締切が近い順に自動で整理して見える化し、やり忘れを防ぐ。
- **使う人**：複数のタスクの締切を管理したい学生。
- **どんな場面で使うか**：日々の課題・提出物・予定を登録し、締切を確認しながら消化していく場面。
- **作らないもの（今回の範囲外）**：複数端末でのデータ同期、アカウント／ログイン機能、締切のプッシュ通知、サーバー側でのデータ保存。

---

## 2. 機能要件（何ができるか）

| ID | 機能名 | できること |
| --- | --- | --- |
| FR-01 | タスク追加 | 利用者がタスク（タスク名・メモ・締切・重要度・ジャンル）を追加できる |
| FR-02 | タスク編集 | 利用者が既存タスクの内容を編集して上書き保存できる |
| FR-03 | タスク削除 | 利用者がタスクを削除できる |
| FR-04 | 完了切替 | 利用者がチェックボックスで完了／未完了を切り替えられる |
| FR-05 | 締切セクション分け | 締切に応じてタスクを「期限切れ／今日／明日／今週／来週／それ以降／期限なし」に自動で分けて表示する |
| FR-06 | 検索 | 利用者がタイトル・メモのキーワードでタスクを絞り込める |
| FR-07 | 絞り込み | 利用者が重要度・ジャンル・完了表示の有無でタスクを絞り込める |
| FR-08 | ジャンル管理 | 利用者がジャンルを追加・改名・削除できる |

---

## 3. 非機能要件（どんな質を満たすか）

| ID | 分類 | 内容（測れる形で） |
| --- | --- | --- |
| NFR-01 | 速さ | タスクの追加・操作・絞り込みの後、1秒以内に一覧が再表示される |
| NFR-02 | 使いやすさ | 説明を読まなくても、タスク名を入力して追加ボタンを押すだけでタスクを登録できる |
| NFR-03 | 安全性 | 入力されたタスク名は HTML エスケープして表示し、スクリプト（XSS）が実行されないようにする |
| NFR-04 | 信頼性 | ブラウザを再読み込み・再起動しても、登録したタスクとジャンルが保持される |
| NFR-05 | 動作環境 | 最新の Web ブラウザ（Chrome など）で、ビルドやインストールなしにファイルを開くだけで動作する |

---

## 4. 制約・前提

- **開発環境・言語**：HTML / CSS / JavaScript（素の JavaScript のみ）。フレームワーク・ビルドツール・パッケージマネージャは使用しない。データはブラウザの `localStorage` に保存する。
- **期間・予算**：授業内の開発期間で完成させる。外部サービス・有料ツールは使用しない。
- **守るべきルール**：データはブラウザ内にのみ保存し、サーバーへ個人情報を送信しない。

---

## 5. 完成の目安

- **FR-01** が、タスク名・締切・重要度・ジャンルを指定して追加でき、一覧に反映される こと
- **FR-04** が、チェック操作で完了状態を切り替え、再読み込み後も保持される こと
- **NFR-01** が、操作後1秒以内に一覧が再表示される を満たしていること
- **NFR-04** が、再読み込み後もデータが保持される を満たしていること
